# 需求文档

更新日期：2026-10-22。项目：AI 零代码应用生成平台（hui-ai-code-mother）。

## 1. 背景与目标

用户通过自然语言描述网页需求，平台调用大模型生成代码，在对话界面持续展示生成过程，并保留应用和对话记录。项目用于个人学习、AI 工程实践和作品展示，目前处于持续迭代阶段。

核心目标是建立“描述需求 → 创建应用 → 对话生成 → 查看产物 → 继续修改 → 发布访问”的流程。现阶段已具备用户、应用、对话、代码生成、Vue 自动构建及静态产物复制部署的基础实现，并完成一个 Vue 博客的本地预览和部署验收；隔离构建和完整任务状态仍待完善。

## 2. 用户角色

| 角色 | 主要需求 | 当前权限边界 |
| --- | --- | --- |
| 访客 | 浏览精选应用、查看应用详情、注册登录 | 精选列表和应用 VO 详情接口可公开访问 |
| 普通用户 | 创建和管理自己的应用、对话生成代码、查看历史、下载源码、部署 | 生成、改名、下载源码、部署仅应用创建者可执行 |
| 管理员 | 管理用户、应用和全站对话记录 | 管理接口通过 `@AuthCheck` 校验；可删除其他用户应用、查看其历史，不能代替创建者生成或部署 |

公开详情中的字段和生成文件的可见范围，仍需作为后续隐私需求进一步收敛。

## 4. 关键业务流程

1. 用户注册登录，首页输入初始需求；服务端先通过 AI 选择生成类型，再创建应用。
2. 前端进入应用对话页，获取应用信息及历史消息；符合条件时自动发送初始需求。
3. 服务端检查应用存在性和创建者权限，先保存用户消息，再按应用记录中的生成类型调用 AI。
4. SSE 展示文本和工具执行过程；HTML/多文件模式在流结束后解析并写盘，Vue 模式在工具执行时写盘。
5. 服务端保存 AI 回复；Vue 模式在有界弹性线程中安装依赖并构建，成功后才发送 `done`。前端重新读取历史并刷新预览；构建、模型或原生文件保存失败均进入错误分支。
6. 用户继续对话修改，或触发部署。Vue 部署等待构建成功后复制 `dist`；HTML/多文件复制源目录。外部静态服务负责发布访问。
7. 应用创建者可下载生成目录中的源码 ZIP。部署成功后后台异步生成封面，上传 COS 并更新应用信息；返回部署地址不表示封面已生成。

删除应用时尝试删除关联对话历史；当前实现不清理生成文件、部署文件、Redis 记忆和 AI 服务缓存。

## 5. 非功能需求

以下为目标要求，尚未全部验收：

| 类别 | 目标 | 当前差距 |
| --- | --- | --- |
| 权限与隔离 | 私有操作按用户校验，模型写文件只能位于应用目录 | 生成/部署有所有者校验；文件工具已限制应用源码目录、拒绝绝对路径/越界/链接；静态资源访问边界仍待完善 |
| 可用性 | 流式完成、失败和取消有明确结果，异常可以重试 | 原生保存和 Vue 构建失败会传播；初始化/流式异常返回 `generation_error`，仅成功发送 `done`；完整取消与任务状态仍待完善 |
| 数据一致性 | 历史、记忆、文件与发布版本具有清晰生命周期 | 缺少生成任务状态、版本快照、跨资源一致性和删除清理策略 |
| 性能与成本 | 控制请求并发、模型使用量和响应时长 | 有缓存、分页限制和构建命令超时；限流、配额、模型超时及应用级生成锁尚待设计 |
| 可维护性 | 配置独立，生成策略可扩展，核心链路可自动验证 | 有工厂、解析/保存执行器、流处理器；AI 测试依赖外部服务，源码定制需维护 |

暂未设定经过压测验证的 QPS、生成耗时或成本指标，不以未经测量的数字作为项目成果。
